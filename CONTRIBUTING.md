# Contributing

Contributions are welcome: bug reports, ideas and pull requests. Italian or English, as you prefer.

## Issues

- **A bug**: what you did, what you expected, what happened instead, and the versions (Claude Code or pi, and Glassbox, shown in the pane's title). A screenshot of the pane helps.
- **An idea**: what you would like to see in the pane and why. For a new section, say where its data would come from.

## Pull requests

1. Fork the repository and branch from `main`.
2. Load the mod from your clone to try it: `claude --plugin-dir mods/glassbox`, or `pi -e .` for pi. The session reloads it on every save.
3. Before opening the pull request, run the checks for what you touched (see "Sviluppare" in the [README](README.md#sviluppare)):

   ```bash
   claude plugin validate mods/glassbox
   claude plugin test mods/glassbox
   python3 -I mods/glassbox/tests/sessions_helper_test.py
   pi/build.sh && pi/test.sh      # only if you touched mods/glassbox/hooks: commit pi/dist too
   ```

4. Keep a pull request to one change, with a test for new behaviour when the code can be tested without a real session (most of `mods/glassbox/hooks` can: see `mods/glassbox/tests/engine.ts`, the fake engine the tests run against).

## How the code is laid out

- `mods/glassbox/hooks/register.tsx` registers the hooks and draws the pane; each section has its state in its own module (`repo.ts`, `files.ts`, `turns-state.ts`, `sessions.ts`, `vox.ts`) and its view in a `view-*.tsx` file.
- `mods/glassbox/hooks/host.ts` holds the few things that differ between Claude Code and pi.
- `pi/src` is the adapter that runs the same code in pi; `pi/dist` is generated by `pi/build.sh` and committed, because pi does not load JSX.
- Code comments are in Italian, the pane's text in English.
